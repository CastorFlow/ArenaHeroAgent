# Lightning 策略说明

本项目当前只保留 **Lightning** 顶层策略。所有单位决策都从每个 Turn 的权威状态重新计算，并结合持久化的路线、访问次数、敌情、射击结果和控制参数。

## 1. 总体目标

Lightning 不是固定脚本队列，而是围绕以下循环运行：

1. 工人维持采集、交付和局部探索；
2. Core 根据资源、生命、护盾、生产、物流和威胁决定行动；
3. 先锋形成近轨屏障并处理贴身威胁；
4. 游侠在中轨进行火控、预测、支援和反突入；
5. 可选 Comet 小队脱离主轨前往信标或指定坐标；
6. 轨道半径、生产结构和 Core 转移可由 Dashboard 热更新。

## 2. 动态轨道体系

策略以 Core 为中心计算分层方形轨道，而不是给所有单位共享一个固定圆环。

- **先锋近轨**：靠近 Core，作为最先接触敌人的近战屏障。
- **游侠中轨内层**：获得射线、支援角度和对贴身敌人的火力覆盖。
- **工人中轨外层**：在不挤占游侠射击位的前提下扩大视野和搜索资源。
- **传感外层**：由当前实际轨道宽度和单位数量动态推导，用于威胁预警。

单位轨道槽位按稳定标识分散，避免所有单位追逐同一个角点。目标角周围障碍过密时可提前换角；持续停滞或小范围震荡会进入临时逃生状态，优先寻找出口更多、访问密度更低的格子，然后回到自己的轨道。

## 3. 威胁分级与防线

可见敌方先锋和游侠会按它们相对 Core 的方形半径、攻击距离、到 Core 的预计时间和穿越下一层防线的时间进行分级。

- 外层接触用于预警和调整巡逻；
- 进入游侠轨道后触发更积极的射击和截击；
- 逼近近轨或能快速攻击 Core 时进入高威胁；
- 高威胁下 Core 优先治疗、修盾或保持战斗锚点。

防线几何来自当前轨道实际占用，而非独立旧模式的固定“近/中/远”半径。

## 4. 工人经济

工人按照优先级处理：

1. 已携带资源时回到 Core 交付；
2. 已确认的可见资源；
3. 可信的历史资源与刷新区域；
4. 本地扩圈探索；
5. 浏览器扩展提供的近距离低可信提示。

策略会避免让大量工人被远距离目标长期占用。资源仓满、Core 入口拥堵、Core 正在转移或敌方战斗单位靠近时，工人会调整目标、等待或撤离。

工人路线记录访问密度、近期位置和目标进度，用于识别：

- 原地停滞；
- 小范围循环；
- 障碍物封闭口袋；
- 已被采空但可能刷新的区块；
- Core 移动造成的交付点变化。

## 5. 生产与资源

生产使用官方 `unit_cost` 根据当前人口计算真实价格。默认长期比例为：

```text
Ranger : Vanguard : Worker = 1 : 1 : 3
```

生产决策综合：

- 用户建造队列；
- 开局工人引导；
- 战斗漏斗或医疗缺口；
- 补兵阈值和优先级；
- 各兵种上限；
- 当前比例偏差；
- 战备资源；
- Core 所在格容量和当前生命/护盾需求。

某兵种比例设为 `0` 会停止该兵种的常规与应急生产；全部比例设为 `0` 可用于囤积资源。上限 `0` 表示不限制，而不是禁止生产。

默认战备资源为 150。只有经济和资源容量允许时才保留这部分资源，避免开局因容量不足而永久停止扩张。

## 6. 先锋行为

先锋主要承担：

- 近轨巡逻和 Core 屏障；
- 清扫相邻敌人；
- 在高威胁方向形成物理阻挡；
- 配合游侠处理突入的先锋或游侠；
- 在复杂地形中避免持续撞墙和震荡。

先锋不再由独立顶层进攻模式拉走。远离 Core 的特殊任务只来自显式启用的 Comet 小队。

## 7. 游侠火控

游侠会先生成合法射击格，再结合敌方运动历史和当前战场上下文评分。主要因素包括：

- 敌人前进、后退、横移或停留的概率；
- 最近射失的目标格和轴线；
- 多名游侠对同一格的覆盖；
- 是否能在敌方视野盲区射击；
- 自身是否会进入不可接受的威胁格；
- 对 Core 防线和其他单位的支援价值。

策略包含对移动敌人的预瞄、对战略相持的 45° 支援、先锋与游侠的协同舞步，以及直接可执行的局部攻击计划。计划在每个 Turn 重新校验，目标消失、路径阻塞或风险变化时不会机械延续旧动作。

## 8. 伤员与医疗缺口

生命较低的游侠会评估回 Core 治疗所需时间，包括回程、Core 队列、治疗和返回火力位的总缺口。若高威胁方向需要持续覆盖，策略会优先寻找健康游侠临时填补该扇区；没有可用替补时，生产系统可在比例和上限允许的前提下补充游侠。

工人、先锋和游侠的治疗都服从 Core 当前资源、入口占用和战斗紧急程度。

## 9. Core 行为

Core 每个 Turn 的主要优先级为：

1. 必要时治疗自身；
2. 在威胁或低护盾时修盾；
3. 在位置容量允许时生产；
4. 为工人交付和治疗服务保留入口；
5. 执行用户目标、信标追随或轨道巡逻；
6. 根据敌情启用退避或追击偏置。

`core_orbit_radius=0` 时不启用自动方形轨道巡逻。设置正数后，Core 会前往相应方形周界并轮转角点。

Core 转移的三种样式：

- `star`：移动过程中保持常规采集和交付。
- `march`：减少采集拖延，让空载工人随 Core 推进。
- `fortify`：移动期间继续采集但暂缓交付，到达后集中回仓。

它们只是 Lightning 内部的物流选择。

## 10. Comet 小队

Comet 是 Lightning 内部的可选远征任务，可追踪当前信标或前往自定义坐标。

派出前会检查：

- 可用先锋和游侠数量；
- Core 周边最低留守数量；
- 成员是否已被其他关键任务占用；
- 目标是否有效。

任务中会：

- 识别附近战斗威胁；
- 让游侠在合法射程内先清障；
- 避免所有成员无脑冲入敌方火力；
- 按伤员阈值撤退并补充成员；
- 可选择让首批成员先在目标前方集合，再统一推进。

关闭任务或改变启用状态时会清理旧编组，避免成员永久被残留状态锁定。

## 11. 热加载与持久化

`arena_hero_tactic.py` 会持续加载策略，并将长期记忆写入运行文件。控制参数发生变化后，下一批 Turn 会读取新值。每个 Turn 都是权威状态替换，策略不会凭空创造单位、坐标或敌人信息。

以下内容不应提交到公开仓库：

- 战术记忆、路线和浏览器情报；
- 战况、Core 轨迹和遥测；
- Agent 状态、日志和控制文件；
- API Key 或 Dashboard Token。

## 12. 可观测性

Dashboard 和叠加层展示：

- Tick、资源、人口和单位数量；
- 当前路线与目标；
- Core 轨迹和战况历史；
- Lightning 威胁、生产和决策计数；
- 中文事件日志。

这些输出用于调试和观察，不改变官方 Turn 的权威性。
